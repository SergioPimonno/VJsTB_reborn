# Таблицы габаритов оборудования — как править и загружать

Файлы собраны 2026-10-23 (источники, достоверность и пояснения — в
[`../EQUIPMENT_DIMENSIONS.md`](../EQUIPMENT_DIMENSIONS.md)). **На сервер ничего не загружено.**
Значения в таблицах найдены в сети и частично являются допущениями (модель в библиотеке
названа коротко): проверьте их и поправьте руками.

| Файл | Что внутри | Строк |
|---|---|---|
| `01_controllers_processors.csv` | контроллеры и видеопроцессоры (Novastar, ROE, PixelHue, Barco) | 15 |
| `02_media_servers.csv` | медиасерверы (disguise, SMODE) | 2 |
| `03_converters.csv` | конвертеры (CVT4K, Lightware, Blackmagic) | 4 |
| `04_monitors.csv` | мониторы и телевизоры | 4 |
| `05_power.csv` | питание: ИБП, AlpenBox, распределители | 11 |

## Колонки

Разделитель — `;`, кодировка UTF-8 (с BOM), десятичная запятая. Excel открывает файл двойным
щелчком.

| Колонка | Смысл |
|---|---|
| `apply` | **Отметка «загружать эту строку»**: `да`, `1`, `x` или `+`. Пустая — строка пропускается. Сейчас пустая везде, чтобы непроверенное случайно не загрузилось |
| `server_kind`, `id`, `name` | запись общей библиотеки (`id` — ключ, по нему идёт сопоставление; не менять) |
| `model` | какая модель принята (справочно) |
| `form_factor` | `RACK` — в стойку, `LOOSE` — россыпью (настольное, лежит на столе или у трассы) |
| `rack_units` | высота в юнитах (для RACK) |
| `width_twelfths` | доля ширины 19″: `12` — целиком, `6` — 1/2, `4` — 1/3, `3` — 1/4. Пишите числом: Excel превращает `1/2` в дату |
| `width_mm`, `height_mm`, `depth_mm` | габариты, мм |
| `weight_kg`, `power_w` | вес и мощность |
| `confidence`, `sources`, `note` | достоверность, ссылки, пояснения (при загрузке игнорируются) |

Правила ячеек: **пустая ячейка — «не менять»** (значение на сервере остаётся как было); **`-`
(прочерк) — «очистить значение»**. Числа можно с запятой или с точкой.

## Как править

1. Откройте нужный файл в Excel, поправьте цифры (источники — в колонке `sources`), у
   проверенных строк поставьте `да` в колонке `apply`.
2. Сохраните как **CSV UTF-8 (разделитель — запятая)** (в русском Excel это `;`). Обычный «CSV
   (разделитель — запятая)» в кодировке Windows тоже читается.
3. В админке: вкладка библиотеки → кнопка **«Импорт габаритов из CSV…»** (рядом с «Импортировать
   library.json…») → выберите один или несколько файлов.
4. Откроется **предпросмотр**: по каждой строке видно «будет записано / без изменений / не
   найдено на сервере / ошибка в строке / не отмечено» и что именно изменится (было → станет).
   Пока вы не нажмёте «Записать на сервер» и не подтвердите, ничего не меняется.
5. Перед записью прежние значения сохраняются в файл `physical-import-backup-….json` рядом с
   первым выбранным CSV. Если резервную копию записать не удалось, запись не начинается.

## Что делает загрузка и чего не делает

- Добавляет в запись библиотеки блок `physical` (юниты, доля ширины, габариты, вес, мощность);
  остальные поля записи не меняются.
- Текущие версии приложения этот блок **не используют** (он нужен будущему Планнеру пультовой) и
  молча игнорируют: никакого видимого эффекта до реализации планнера нет.
- Пересобранная админка (jar от 2026-10-23) сохраняет `physical` при обычной правке записи в
  формах. **Старую сборку админки на записях с `physical` не использовать**: её формы не знают
  этого поля и сотрут его при сохранении записи.
- Кофры (`CASE`) и кабинеты уже имеют размеры в своих полях; здесь они не нужны. Рэк-кофров на
  сервере нет вообще — их нужно будет завести отдельно.
