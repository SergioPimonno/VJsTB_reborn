# Прогон и расширение тестов клиента

## Окружение (Windows, отдельного Maven нет)

Maven берётся из плагина IntelliJ IDEA:

```bash
export JAVA_HOME="/c/Program Files/Java/jdk-21.0.10"
export PATH="/c/Program Files/JetBrains/IntelliJ IDEA 2025.3.1.1/plugins/maven/lib/maven3/bin:$JAVA_HOME/bin:$PATH"
```

Номер версии IDEA может измениться — проверить `ls "/c/Program Files/JetBrains/"`.

## Запуск

```bash
mvn test
```

Из корня `VJsTB_reborn`. **Всегда полный прогон, не выборочный** (`-Dtest=...`
только для локальной отладки одного класса, не как подтверждение «всё зелено»).
Релизный критерий — **0 failures на полном прогоне**.

Карта всех 43 тест-классов / ≈350 методов с описанием покрытия — `TESTS.md` в
корне репозитория. Свериться с ней, прежде чем решать, что фича «не покрыта».

## Конвенции тестирования проекта

- **Никакой реальной сети.** Sync-клиенты (`sync.*`) тестируются на
  зафиксированном JSON, зеркалящем ответ сервера. Ping/scan (`service.Network*`)
  тестируют только построение команды, не запуск процесса.
- **Бинарные форматы (NovaLCT `.scr`)** — golden-байтовые регрессии против
  РЕАЛЬНЫХ файлов NovaLCT, подтверждённых загрузкой обратно в неё. Не подменять
  их round-trip'ом через собственный писатель (это отдельный, более слабый вид
  проверки — см. `NovaLctScrParserTest`).
- **Визуальные схемы** (`*SchemaImageWriter`) — только структурные инварианты
  размера (растёт с шириной/числом точек, не падает на краевых входах), не
  побайтовое сравнение.
- **GUI** — «дымовые» тесты (`GuiSmokeTest`, `ScenarioFeatureGuiTest`,
  `PowerStagePanelChainRowClickTest`): строят реальные окна и закрывают, не
  показывая; **пропускаются в headless-среде** — если `mvn test` идёт без
  дисплея, эти классы молча скипаются, это нормально.

## Добавление теста

- Копируй ближайший существующий класс как образец — стиль в проекте единый.
- **Class-javadoc объясняет ПОЧЕМУ тест существует** (какой баг-репорт, что
  ломалось раньше). Это часть документации, а не формальность — заполняй.
- Имена методов — предложения-поведения (`hidingCabinetRemovesItFromChains`,
  `resolvesControllerStoredOnAnotherScreenOfTheSameScene`), не `test1`.
- Для доставки Swing-событий тестируй через реальный `dispatchEvent` на самый
  глубокий компонент, а не вызовом слушателя напрямую (см.
  `PowerStagePanelChainRowClickTest` — так ловятся баги «слушатель висит только
  на родителе»).

## Тесты серверного репозитория (ledscheme-server) — другой репозиторий

`mvn test` в `C:\Development\ledscheme-server` отдельно. Там `@SpringBootTest` +
`MockMvc` + H2 in-memory, **общий Spring-контекст на весь прогон surefire, БЕЗ
отката между тестами**. Если тест должен проверить «записи гарантированно нет» —
не полагайся на порядок выполнения, создай и сразу удали её сам перед проверкой
(наступили на это с тестом 404 для `VERSION_MANIFEST`).

## Связанные скиллы

- Живая проверка в собранном приложении (не только тесты) — скилл `test-build`.
- Перед релизом полный прогон обязателен — скилл `release-client`, шаг 5.
