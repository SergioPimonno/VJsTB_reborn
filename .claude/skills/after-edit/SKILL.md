# Протокол «после правки»

Пользователь сам тестирует сборки и часто просит откатить правку. Поэтому
**перед каждой пересборкой предыдущее состояние сохраняется**, а не затирается.

## Когда

После любой правки кода/ресурсов клиента (`src/main`, `src/test`, `pom.xml`
— если влияет на jar). Одна пересборка на логически завершённую пачку правок
(не после каждого `Edit`), но обязательно ДО того, как сообщишь «готово».
Правки только документации/скиллов пересборки не требуют.

## Шаги

1. Тесты по теме правки + при существенных изменениях полный `mvn test`
   (скилл `run-tests`). Красные тесты — не передавать билд как готовый.
2. Одной командой — снимок предыдущего + сборка:
   ```bash
   tools/test-build/snapshot-and-build.sh "что изменено — одной строкой"
   ```
   Скрипт:
   - копирует текущий `testbuild/led-scheme-test.jar` в
     `testbuild/previous/<дата-время>-<HEAD>/`;
   - рядом кладёт `uncommitted.patch` (`git diff HEAD` на момент ДО сборки),
     `untracked.txt` и копии новых файлов — полное состояние для отката кода;
   - дописывает строку в `testbuild/previous/INDEX.md`;
   - хранит 10 последних снимков, старые удаляет;
   - собирает `mvn -DskipTests package` и копирует jar в `testbuild/`.
   `testbuild/` вне git — ничего не коммитится (Золотое правило 1).
3. Сообщи пользователю одной-двумя строками: что в билде нового, время сборки
   и **как откатить** (см. ниже). Не пересказывай код.

## Откат правки по просьбе пользователя

- **Только билд** (быстро): `cp testbuild/previous/<снимок>/led-scheme-test.jar
  testbuild/led-scheme-test.jar` — пользователь сразу тестирует прежнее поведение.
- **Код**: правки, ещё не закоммиченные, откатываются точечно (`Edit` обратно
  или `git checkout -- <файл>` для файлов, затронутых ТОЛЬКО откатываемой
  правкой). Если нужно вернуть состояние на момент снимка —
  `uncommitted.patch` + `untracked/` из каталога снимка. Если правка уже
  закоммичена (и тем более запушена) — откат только новым коммитом
  (`git revert`) и только по команде пользователя; историю не переписывать.
- Перед откатом посмотри `testbuild/previous/INDEX.md` и покажи пользователю
  список снимков, если непонятно, какой нужен.
- Откат одной правки не должен задеть соседние: сверяйся с `git diff` и
  не использовать `git checkout .` / `git reset --hard` без явной просьбы.

## Какие процессы можно закрывать

**Только процессы приложения: командная строка содержит `led-scheme`,
`vjstb`, `ave_tb` или `AVE_ToolBox`.** Любые другие Java-процессы (Minecraft,
IDE, Maven, чужие утилиты, IntelliJ) НЕ трогать — ни по имени `java`/`javaw`,
ни блочным `taskkill`, ни `Stop-Process` без проверки командной строки.
Инцидент 2026-08-11: блочный `taskkill` по `javaw` убил фоновый Minecraft
пользователя.

Закрывать процесс имеет смысл только для проверки через computer-use (скилл
`test-build`, с предупреждением пользователя) — для обычной передачи билда
пользователю закрывать ничего не нужно, он перезапускает сам. Скрипт с флагом
`--restart` делает это правильно (фильтр по командной строке).

## Связанные скиллы

- `test-build` — сборка/запуск/живая проверка, ярлык на рабочем столе.
- `run-tests` — прогон тестов.
- `release-client` — релиз; правила версий/тегов — `VERSIONING.md`.
