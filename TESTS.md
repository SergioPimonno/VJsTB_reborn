# Карта тестов — VJsTB_reborn (клиент)

Инвентаризация всего тестового покрытия клиента для быстрой ориентации агентов.
Собрано из `src/test/java/**` на момент коммита `690d1e8` (v2.2).

- **Фреймворк**: JUnit 5 (`junit-jupiter` 5.10.3), `maven-surefire-plugin`.
  Компиляция под Java 21 (`maven.compiler.release=21`).
- **Прогон**: `mvn test` в корне `VJsTB_reborn`. Перед релизом — полный прогон,
  0 failures (скиллы `run-tests`, `release-client` шаг 5).
- **Всего**: на момент v2.6 — 861 тест (по surefire), 0 failures; разделы ниже
  написаны по состоянию на v2.2 и дополнены разделами к более поздним версиям.
- **Принципы проекта**:
  - Никакой реальной сети — sync-клиенты тестируются на зафиксированном JSON,
    ping/scan тестируют только построение команды, не запуск процесса.
  - Бинарные форматы (NovaLCT `.scr`) — golden-байтовые регрессии против
    РЕАЛЬНЫХ файлов NovaLCT, подтверждённых загрузкой обратно.
  - Визуальные схемы (rigging / vehicle load image writers) — только
    структурные инварианты размера, не побайтовое сравнение.
  - GUI — «дымовые» тесты: строят реальные окна и закрывают, не показывая;
    пропускаются в headless-среде.

### `StructureCalcTest` (22) — количество железа объёмной башни (Phase 2.1)

### `RiggingCalcTest` (15) — распределение веса подвешенного экрана по точкам
(Метод грузовых площадей, см. `RIGGING_CALC_NOTES.md`.) Равномерный экран — ровно
по точкам; скрытые кабинеты не дают веса и не смещают распределение; over-capacity
флаг при превышении WLL тали; без capacity — никогда не флагуется; `HoistType`
из библиотеки важнее ручной capacity; висячий `hoistTypeId` откатывается на
ручную; `suggestPointCount` — геом. минимум 2 без известной ширины модуля, по
физическому пролёту, растёт при нагрузке > capacity; `compute` вставляет отступ
от края (500 мм), узкий экран пропускает отступ, tie-break к центру, не влево.
Точки теперь расставляются от краёв ФЕРМЫ (`TrussCalc`), не экрана — 3 новых
теста: симметричный свес фермы длиннее экрана двигает крайние точки в обе
стороны; ручной несимметричный отступ сдвигает все точки на ту же величину;
ферма короче экрана — точки внутри пролёта фермы, не экрана. При
неизменённых truss-полях экрана (умолчание) числа идентичны версии без ферм —
чисто регрессионное свойство, не отдельный тест.

### `MinimalKitCalcTest` (7) — DP-подбор минимального комплекта кусков
Вынесенное из `CableSpecCalc.minimalKit` DP-ядро, переиспользуемое `TrussCalc`.
Два режима отбора при нескольких комплектах с одинаковой минимальной суммой:
`solve` (минимум ЧИСЛА кусков — нужно кабельной сплайсовке) против

регрессионный тест на баг-репорт 2026-09-14: каталог 1/2/0.5м, цель 1.5м —
`solve` берёт один кусок 2м (меньше кусков, но 33% излишка), `solveMinimizing
Overage` — точную комбинацию 1+0.5 без излишка вовсе. Плюс примеры
пользователя (2.5м→2+0.5, 7м→2+2+2+1), пустой/некорректный каталог,
неположительная цель.
