# Список изменений AVE_ToolBox (VJsTB_reborn)

Формат пометок: **[Новая функция]**, **[Изменение]**, **[Багфикс]**.
История версий до 2.3 — в `versions.txt` и в GitHub Releases
(https://github.com/SergioPimonno/VJsTB_reborn/releases).

## v2.3

Объединяет работу трёх параллельных веток разработки. Крупнейшее — новый
раздел «Сетевой менеджер».

### [Новая функция] Сетевой менеджер (третья вкладка этапа «Сигнал»)

Раздел для описания компьютерных сетей площадки в стиле Cisco Packet Tracer.
В рамках одной сцены создаётся несколько сетей; в каждую добавляются блоки —
либо взятые из общей схемы сигнала (резолвятся вживую: переименование узла
схемы сразу видно в менеджере), либо новые из каталога типов сетевого
оборудования. Возможности:

- **Топология с портами и связями**: линки строятся кликами порт-в-порт,
  ломаются точками излома (двойной клик, Shift-снаппинг — как у общей схемы),
  выпрямляются из ПКМ-меню; цвет линий — по цвету сети.
- **Живой пинг** устройства (ПКМ → «Пинговать») — непрерывный поток строк
  реальной команды ОС в немодальном окне, с корректной кодировкой вывода на
  Windows (`chcp 65001` в изолированной консольной сессии).
- **Сканирование диапазона IP** («Найти устройства») — параллельный пул
  потоков, отвечающие адреса добавляются в выбранную сеть одной кнопкой.
- **Таблица адресов** — живое окно со сводкой всех устройств всех сетей
  сцены, обновляется на каждое изменение модели.
- **Обнаружение конфликтов IP** внутри сети — красная рамка блока и подпись
  «⚠ конфликт IP», строка в таблице адресов целиком красным.
- **Веб-интерфейс**: явный флаг «есть веб-интерфейс» + сохранённый URL, ПКМ →
  «Открыть веб-интерфейс».
- drag-n-drop блоков из палитры, снаппинг блоков и точек излома к другим
  блокам/точкам.

Новая общая библиотека `NetworkDeviceType` / `NetworkDeviceCategory`
(`ledscheme-model`, вид сервера `LibraryItemKind.NETWORK_DEVICE`) — каталог
типов, синхронизируется как `CaseType` / `VehicleType`. Данные проекта —
`Scene.networkManagerPlan`, локальные модели `Network` / `NetworkManagerPlan` /
`NetworkDevicePlacement` / `NetworkLink` / `NetworkLinkWaypoint`. Подробности —
`NETWORK_MANAGER_NOTES.md`.

### [Новая функция] Резерв на уровне отдельной карты контроллера

Для контроллеров с несколькими выходными картами (пул Ethernet-портов —
например, Novastar H2, 2 карты) резерв теперь назначается **покарточно**, а не
только целым контроллером: ПКМ по заголовку карты в сетке портов этапа «Сигнал»
помечает карту как ждущую связки, ЛКМ по заголовку другой карты (в т.ч. другого
контроллера сцены) завершает связку — та карта становится основной, помеченная
резервной для неё. Механика зеркальна резерву всего контроллера
(`AppModel.setControllerBackupLink`): порты резервной карты целиком уходят под
подхват (`isPortReservedAsBackup`), уже существующим и новым цепочкам основной
карты автоматически проставляется `backupPortNumber` на зеркальный порт
резервной карты, снятие связки его сбрасывает, удаление контроллера убирает
висячие ссылки. Данные — `ControllerInstance.cardBackupLinks`
(`Map<индекс пула → CardBackupLink>`); новые методы `AppModel.setCardBackupLink`
/ `isCardReservedAsBackup` / `isCardLevelBackupPort` / `applyCardLevelBackupPort`.

### [Багфикс] Список контроллеров этапа «Сигнал» не растягивался под новый контроллер

Добавленный контроллер (например, 4-й) не появлялся в списке, панель не
скроллилась: `UiKit.recapHeight()` пересчитывает только `maximumSize` секции, но
без `revalidate()`/`repaint()` родительского `BoxLayout` (и `JScrollPane` боковой
панели выше) новый `preferredSize` не долетал до вьюпорта. У секции цепочек эта
пара вызовов уже была — секции контроллеров её не хватало.

### [Новая функция] Горячая клавиша инструмента общей схемы «Перемещение» ↔ «Соединение»

На «Общей схеме» (и в Питании, и в Сигнале) — горячая клавиша, мгновенно
переключающая активный инструмент холста между «Перемещение» и «Соединение»,
по умолчанию **Пробел**. Срабатывает только когда открыта именно «Общая схема»
(не «Расключение экрана») и фокус не в поле ввода. Синхронизирует и вид кнопок
инструмента на боковой панели. Переназначается через **Персонализация →
Горячие клавиши** (`HotkeyAction.TOGGLE_SCHEMA_INTERACTION`), описана в справке
«Горячие клавиши».

### [Новая функция] Раздельная ориентация гнёзд разъёмов для Сигнала и Питания

Настройка «Гнёзда разъёмов у верхнего/нижнего края блока» на узлах общей схемы
раньше была одна на обе схемы. Теперь это две независимые настройки — своя в
группе «Сигнал», своя в «Питание» (`UserProfile.signalConnectorsVertical` /
`powerConnectorsVertical`, маршрутизатор `isConnectorsVertical(SchemaMode)`).
`SchemaCanvasPanel` спрашивает ориентацию с учётом текущего режима схемы.

### [Новая функция] Калькулятор транспорта — доработки

- **«+ Новый тип машины…»** в карточке машины визуализатора — по образцу
  «+ Новый тип кофра…»: создаёт тип в личной библиотеке и предлагает отправить
  в общую на модерацию (`VehicleTypeDialog`).
- **«Убрать все»** в карточке машины — симметрична «Разместить всё», очищает
  раскладку именно этой машины (с подтверждением, если там что-то есть).
- Автоматическая раскладка загрузки.

### [Новая функция] «Форма экрана» отдельным всплывающим окном

Предпочтение «Открывать отдельным всплывающим окном, а не областью в
«Сетапе»» (группа «Общие») — кнопка «Изменить форму экрана» тогда открывает
живое окно `ShapeEditorDialog`, которое следует за текущим выбранным экраном.

### [Новая функция] Папка экспорта по умолчанию

Предпочтение «Папка экспорта…» (группа «Общие») — корневая папка, которая
подставляется в экспортах схем/масок/пресетов, пока не выбрана явно на
конкретном этапе (раньше была жёстко зашита как `~/Documents/Video`,
см. `OutputPaths`).

### [Новая функция] Блок «Статистика сцены» на этапах Питание и Сигнал

Переключаемый (предпочтения, группы «Питание»/«Сигнал») блок под статистикой
активного экрана — суммарные показатели по всей сцене, видны независимо от
«Показать все экраны сцены».

### [Новая функция] Общий список недавних цветов

`RecentColorsChooserPanel` — недавно выбранные цвета переиспользуются между
разными местами выбора цвета (`PersonalizationDialog` и др.).

### [Новая функция] Экспорт NovaLCT: экран, расключённый несколькими контроллерами

Если один экран расключён с двух и более контроллеров сцены (типовой случай —
левая/правая половина на разных Sending Card), экспорт каждого контроллера
раньше писал полную сетку экрана с записями только для своих колонок —
остальные видимые ячейки оставались без записи, и NovaLCT отклоняла импорт.
Теперь экспорт берёт габаритный прямоугольник ячеек этого контроллера и
пере-индексирует его в собственную локальную сетку (не покрытые ячейки внутри
прямоугольника — blank-сентинел `card=0xFF`, как для вырезов). Диалог
спрашивает, писать кусок как **отдельный screen** (Coordinate X/Y = 0) или
**сохранить положение** на канвасе NovaLCT — тогда подставляется редактируемый
пиксельный оффсет (`minCol×cabW` / `minRow×cabH`). Формат: Standard (Coordinate
X в заголовке), если сдвиг по Y = 0 и кусок ровный; иначе Complex — сдвиг по Y
вписывается в пиксельные X/Y каждой карты, т.к. Standard Screen Y-координату
экрана не хранит. Поле Coordinate X (`0x141`/`0x14d`) в `writeStandardCore`
переведено с одного байта на полный LE16. `NovaLctScrWriter.writeResolvedSubScreen`,
`NovaLctControllerResolver.controllersWiringScreen`,
`NovaLctControllerExportDialog.askSubScreenPlacement`. Подробности —
`NOVALCT_EXPORT.md` §5.

### [Новая функция] Экспорт NovaLCT: контроллер с Complex- и обычными экранами — один файл

Раньше, если контроллер затрагивал несколько экранов и хотя бы один имел неровную
(Complex) раскладку, весь мультиэкранный экспорт блокировался. По двум реальным
образцам NovaLCT (`standart+complex.scr`, `complex+complex.scr`) разобран формат
мультиэкранного `.scr` со **смешанными** блоками (Screen1 Standard + Screen2
Complex и т.п.) и реализован `NovaLctScrWriter.writeMixedMultiScreen` (golden-byte
тесты). Теперь экспорт делит затронутые экраны: обычные проходят прежнее
ветвление — сшить в одно полотно (Combine) либо разными screen-ами (Separate),
Complex-экраны добавляются своими блоками, всё пакуется в **один** `.scr` (импорт
в NovaLCT заменяет конфигурацию целиком, поэтому у контроллера строго один файл).
Порядок блоков — по возрастанию (Sending Card, Port). `MixedScreen` /
`ComplexScreenBlock` / `resolvedStandardScreen` / `resolvedComplexScreen`.
Подробности — `NOVALCT_EXPORT.md` §4.

### [Изменение] Диалог «Предпочтения» сгруппирован по этапу работы

Разделы перестроены с технических подразделов («Холст и сцена» / «Общая
схема — соединения» / «— узлы и автозаполнение» / «— нагрузка») на группировку
**по этапу работы**: «Общие», «Сигнал», «Питание», «Генерация масок»,
«Синхронизация». «Сигнал» и «Питание» — зеркальные пары одинаковых
переключателей; из подписей убраны ставшие лишними префиксы «Сигнал:» /
«Питание:», подсказки переписаны под новую структуру. Настройки без привязки к
этапу (форма экрана, папка экспорта) — в «Общих».

### [Изменение] Руководство и интерактивные примеры под v2.3

Встроенное «Руководство» (`GuideDialog.DEFAULT_SECTIONS`) дополнено разделами
**«Сетевой менеджер»** и **«Калькулятор транспорта»**; разделы «Общая схема:
основы» (хоткей «Перемещение ↔ Соединение» на Пробел) и «Кастомизация и
предпочтения» (группировка «Предпочтений» по этапу, раздельная ориентация
гнёзд, «Папка экспорта…», «Форма экрана отдельным окном», блок «Статистика
сцены») переписаны под текущее поведение. `README.md` — те же добавления.

Добавлен набор из 7 пошаговых экскурсов по этапам работы (Сетап / Питание /
Сигнал / Сетевой менеджер / Генерация масок / Вывод / Библиотеки) для синглтона
`INTERACTIVE_SCENARIOS`. Текстовый мастер — `interactive-scenarios.seed.json`
(корень репо); каждый из 52 шагов несёт скриншот реального UI, 11
навигационных шагов — кликабельный хотспот на нужной кнопке. Конвейер сборки
(JUnit-генератор скринов `ScenarioShotSpike` → `build_full_scenarios.py` →
`push_scenarios.py`) — `tools/interactive-scenarios/`. На клиенте сервером
ничего не навязывается, пока админ не опубликует.

### [Изменение] Документация проекта разбита на несколько файлов

Монолитный `CLAUDE.md` разделён на индекс `CLAUDE.md` + `ARCHITECTURE.md` +
`TESTS.md`; процедурные разделы вынесены в `.claude/skills/` (`run-tests`,
`test-build`, `deploy-server`, `release-client`, `add-library-singleton`).
На поведение приложения не влияет.

### [Багфикс] Совместимость сохранённых профилей со старой настройкой ориентации разъёмов

Профиль, сохранённый до разделения настройки ориентации гнёзд на сигнал/
питание, хранил единое поле `connectorsVertical`. При первом чтении такого
профиля значение теперь переносится на **обе** новые настройки
(`@JsonSetter("connectorsVertical")` в `UserProfile`), иначе после обновления
ранее выбранная ориентация молча сбрасывалась бы в значение по умолчанию.

### [Багфикс] Калькулятор транспорта: «Добавить сюда» игнорировал выделенный стек

Кнопка «Добавить сюда» всегда штабелировала кофр в стопку в левом верхнем углу
машины, а не в выделенный кликом стек. Теперь при выделенном стеке того же типа
(не на пределе высоты штабеля) наращивается именно он; прежнее поведение
сохранено, когда подходящего выделения нет.

### [Багфикс] Подпись порта на схеме расключения при нескольких контроллерах

`SchemeRenderer` брал имя карты по сырому индексу `getCards().get(poolIndex)`,
который считает все карты подряд, включая чисто входные без Ethernet-выходов —
для контроллеров с входной первой картой (например, H2-серии Novastar) подписи
портов уезжали на соседнюю карту. Теперь резолвится тем же способом, что и сама
нумерация портов, по контроллерам всей сцены (`ControllerType.sendingCardAt`
сделан публичным в `ledscheme-model`).

### [Багфикс] Обновление на Windows: `.bat`-скрипт не выдерживал паузу

`UpdateManager.applyAndRestartWindows` использовал `timeout /t`, который у
detached-процесса без консоли мгновенно падает и не ждёт — обновлённый файл не
успевал разблокироваться, оставалась старая версия. Заменено на
`ping -n 2 127.0.0.1 >nul`.

### [Багфикс] Экспорт NovaLCT для контроллера не первого в сцене давал пустой шаблон

Проект с несколькими одноэкранными контроллерами (по одному MCTRL4k на экран):
в NovaLCT загружался только экран первого контроллера, у остальных импорт
падал. Одноэкранная ветка экспорта резолвила цепочки заново через
`ScreenLogic.cardAndLocalPort`, который отсчитывает локальный порт с нуля по
контроллерам самого экрана — для контроллера, не первого в сцене, сквозной
номер порта его цепочек выходит за собственную ёмкость (17-й порт при 16), и
каждая цепочка отбрасывалась → `.scr` без единой кабинетной записи, NovaLCT
такой файл отклоняет. Теперь одноэкранный контроллер-центричный экспорт
использует уже правильно разрешённые записи `NovaLctControllerResolver`
(смещение порта — `AppModel.portOffsetOf` по всем контроллерам сцены);
`NovaLctScrWriter.writeForResolvedScreen`.
