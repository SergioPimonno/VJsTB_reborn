# LED Scheme Designer

Настольное приложение (Java 21 + Swing) для проектирования LED-экранов и их
коммутации: **проект → сцена → экран → LED cabinets**, с общими библиотеками
оборудования, схемами расключения питания/сигнала по цепочкам (daisy chain),
блок-схемой всей площадки (щиты, дистрибьюторы, медиасерверы, контроллеры) и
контролем электрической/пропускной нагрузки. Весь интерфейс — внутри
приложения; данные хранятся локально в JSON, обновление версии — из самого
приложения (см. [«Обновление версии»](#обновление-версии)).

Веб-интерфейс в этой архитектуре не используется — он планируется отдельно, в
версии 2.0, для серверного модуля (синхронизация библиотек оборудования между
рабочими местами, раздача обновлений, облачный архив проектов).

## Интерфейс: этапы работы

По аналогии со страницами DaVinci Resolve / Pixera работа разбита на этапы,
переключаемые панелью под верхним меню:

- **Сетап** — состав проекта (проекты → сцены → экраны), параметры сетки
  экрана, форма/тип кабинета по ячейкам, прериг (кол-во кабинетов по типам,
  суммарные вес и мощность сцены, точки подвеса, мини-превью раскладки).
- **Питание** — холст экрана + построение цепочек расключения питания по
  фазам L1/L2/L3, контроль нагрузки на цепочку (ёмкость разъёма/автомата) с
  предупреждением и подтверждением превышения.
- **Сигнал** — холст экрана + расключение по портам контроллера, с пометкой
  резервных (бэкап) портов и контролем пропускной способности порта.
- **Генерация масок** — канвасы (виртуальные выходные кадры компоновки
  контента, как Advanced Output), экспорт тестовых масок (Pixel Grid) и
  пресетов под медиасерверы — сейчас Resolume (XML Screen Setup), After
  Effects — заготовлено, ждёт образца формата.
- **Вывод** — выбор папки и формирование пакета документации проекта
  (JPEG-схемы питания/сигнала каждого экрана и сцены целиком, блок-схема
  площадки, текстовые отчёт и спецификация оборудования).
- **Библиотеки** — общие для всех проектов справочники: кабинеты,
  контроллеры, пресеты оборудования общей схемы (щиты/дистрибьюторы/
  медиасерверы/конвертеры), кабели/переходники.

Общая схема площадки (щиты → дистрибьюторы → кабинеты экранов, и то же для
сигнала) редактируется прямо на холстах Питание/Сигнал: узлы с гнёздами
разъёмов, структурированная подпись связи (N×тип, с метражом для питания),
произвольная маршрутизация линий с точками излома, узел-экран можно
показывать блоком или уменьшённой схемой расключения (переключатель в
Персонализации).

Верхнее меню (Настройки / Инструменты / Персонализация / Справка) даёт доступ
к расположению файла данных, импорту/экспорту библиотеки кабинетов,
переключению тёмная/светлая тема, настраиваемым горячим клавишам, проверке
обновлений и иллюстрированному руководству.

## Возможности

- Проекты → сцены → экраны (создание/удаление, списки динамической высоты).
- Общие библиотеки оборудования (этап «Библиотеки», один набор на всё
  приложение, с импортом/экспортом в JSON):
  - **Кабинеты** — физические размеры, разрешение, потребление, вес; форма
    (прямоугольная/треугольная/угловая/круглая) с реальной отрисовкой формы в
    схемах — треугольная рисуется настоящим треугольником с настраиваемым
    углом (0°/90°/180°/270°, шаблон на уровне типа + переопределение по
    конкретной ячейке через радиальное меню), а не декоративной меткой;
    прямоугольные кабинеты сохраняют реальное соотношение сторон.
  - **Контроллеры** — порты вывода/ввода, пропускная способность (расчёт
    предельных пикселей по формуле NovaStar), Loop-порт, комплектация картами
    для модульных моделей (Novastar H-серии и т.п.).
  - **Пресеты оборудования** — щиты/дистрибьюторы/медиасерверы/конвертеры для
    быстрой вставки узла в общую схему, с комплектацией картами/разъёмами.
  - **Кабели/переходники** — мини-конструктор: выбор пары разъёмов (по
    принятой номенклатуре папа/мама, включая USB-C и Thunderbolt) вместо
    свободного текста; предлагаются вдобавок к встроенным пресетам при подписи
    связи схемы.
  - Разъёмы питания и карты контроллеров редактируются на месте (без
    удаления и повторного добавления, чтобы не рвать уже проведённые связи
    схемы); числовые поля (колонны/строки, счётчики, размеры) принимают
    простые арифметические выражения вроде `128*40`.
- Экран собирается из сетки rows × cols кабинетов одного типа; характеристики
  экрана (разрешение, габариты, вес, суммарное потребление, нагрузка по фазам)
  считаются автоматически. Нумерация кабинетов на схеме — с 1,1. Деактивация
  (скрытие) отдельных ячеек — задаёт непрямоугольную форму экрана.
- **Построение цепочек**: выбор фазы (питание) или порта (сигнал) сразу
  начинает новую цепочку. Кабинеты добавляются кликом, протяжкой при зажатой
  ЛКМ или стрелками клавиатуры; `Esc` завершает и сохраняет цепочку. Цепочки
  хранятся на уровне сцены — независимого менеджера цепочек, что снимает
  ограничение «одна цепочка — один экран»: цепочка физически может проходить
  через несколько экранов сцены.
- **Быстрое подключение** (как в NovaLCT): протяжка ЛКМ по холсту выделяет
  прямоугольную область кабинетов, радиальное меню с пиктограммами предлагает
  один из 8 шаблонов серпантина — вся область прописывается одним действием,
  скрытые и уже занятые кабинеты пропускаются без разрыва маршрута.
- **Контроль нагрузки** (Питание/Сигнал): расчёт суммарной мощности/пикселей
  цепочки против ёмкости разъёма/автомата или порта контроллера —
  предупреждение прямо у цепочки, подтверждение («Я знаю») при осознанном
  превышении, блокировка формирования пакета документации, пока есть
  неподтверждённые перегрузки. Запас по умолчанию — 92,6% ёмкости разъёма для
  щитов/источников, 100% для блоков распределения (настраивается по блоку).
- **Сигнал**: сетка портов контроллера — ЛКМ начинает цепочку на порт, ПКМ
  переключает пометку «бэкап» (резервный порт не требует расключения
  кабинетов, но резервирует ёмкость).
- **Общая схема площадки**: узлы оборудования (источник/распределение/
  конвертер/медиасервер/контроллер/экран/прочее) с гнёздами разъёмов,
  структурированные подписи связей, произвольная маршрутизация линий
  (с привязкой Shift к краям узлов и другим точкам излома, как в yEd),
  собственный цвет для каждой линии, масштабирование колесом (Ctrl) и
  перемещение по холсту зажатой средней кнопкой мыши, экспорт в JPEG
  (обычный вид и «тестовый» — с уменьшённой схемой расключения внутри блока
  экрана). Наведение на предупреждение о перегрузке блока поясняет причину.
- **Первый запуск**: короткий интерактивный тур по интерфейсу и персонализации
  (повторно — через меню «Справка»).
- **Обновление версии**: пункт меню «Настройки → Обновить версию…» показывает
  список доступных версий (`versions.txt` в этом репозитории) и качает нужную
  прямо из GitHub Releases — см. [«Обновление версии»](#обновление-версии).
- **Отмена последнего действия** (Ctrl+Z, многоуровневая) для операций
  редактирования экрана: цепочки, скрытие кабинета, позиция, форма/тип ячейки.
- Настраиваемые горячие клавиши (Настройки → Горячие клавиши), масштабирование
  холста (Ctrl+колесо), автосохранение в локальный JSON.

## Горячие клавиши

Основные хоткеи настраиваются (Настройки → Горячие клавиши); ниже —
поведение по умолчанию:

| Клавиши | Действие |
|---|---|
| `Ctrl+Z` | Отменить действие (везде) |
| клик по фазе/порту | Начать новую цепочку (Питание/Сигнал) |
| клик / зажатая ЛКМ / стрелки | Добавить кабинеты в строящуюся цепочку |
| `Esc` | Завершить и сохранить цепочку |
| ПКМ по порту (Сигнал) | Переключить пометку «бэкап» |
| `Del`/`Backspace` | Удалить выделенное в списке/скрыть кабинет под курсором |
| `Ctrl`+колесо | Масштаб холста |

## Обновление версии

`Настройки → Обновить версию…` читает список версий из [`versions.txt`](versions.txt)
в этом репозитории (ветка `master`) и предлагает скачать выбранную версию
напрямую из [GitHub Releases](https://github.com/SergioPimonno/VJsTB_reborn/releases).
Сравнения версий нет — пользователь сам решает, какую ставить. На Windows,
если приложение запущено из jar, обновление применяется автоматически
(скачивание → подмена jar → перезапуск); в остальных случаях скачанный файл
просто открывается.

Чтобы опубликовать новую версию:

1. Собрать и протестировать релиз, поднять версию в `pom.xml`/`AppInfo.java`.
2. Создать git-тег и GitHub Release с активами `led-scheme-v{X.Y}.jar`
   (Windows/кроссплатформенный jar) — macOS-сборка (`.dmg` со встроенным
   рантаймом) добавляется в тот же релиз автоматически через
   `.github/workflows/release-macos.yml` по пушу тега `v*`.
3. Добавить/включить строку в `versions.txt` (`версия|тег|available|заметка`,
   `available=no`, пока активы ещё не загружены — включить в `yes`, когда
   релиз полностью готов на всех платформах).

## Стек и структура

Java 21, Swing + Java2D (UI), FlatLaf (тёмная/светлая тема), Jackson (JSON),
`java.net.http` (проверка обновлений), без БД и сервера. Сборка — Maven.

```

  App.java, AppInfo.java     точка входа (main), тема, метаданные версии
  model/                     POJO-модель: Project/Scene/Screen/CabinetInstance,
                             CabinetType/ControllerType/EquipmentPreset/CableType

                             SchemaNode/SchemaEdge/EdgeWaypoint (общая схема),
                             ContentCanvas/CanvasPlacement (канвасы), Workspace

    PowerCalc/SchemaLoadCalc  расчёт электрической/пропускной нагрузки цепочек
  update/
    VersionManifest           чтение versions.txt (список версий)
```

## Хранение данных

Рабочее пространство (все общие библиотеки + все проекты) хранится в одном
JSON-файле:

```
%USERPROFILE%\.led-scheme\workspace.json   (Windows)
~/.led-scheme/workspace.json               (Linux/macOS)
```

Файл создаётся автоматически при первом сохранении. Библиотеку кабинетов
можно отдельно экспортировать/импортировать в произвольный JSON-файл (этап
«Библиотеки» или меню «Инструменты»).

## Запуск в IntelliJ IDEA

1. `File → Open…` → выбрать папку проекта (где `pom.xml`); IDEA распознает Maven.
2. Дождаться загрузки зависимостей (панель Maven → Reload).
3. Запустить класс `com.vjstb.ledscheme.App` (зелёная стрелка Run).

Требуется JDK 21+ (Project Structure → SDK).

## Сборка и запуск из терминала

Исполняемый jar со всеми зависимостями:

```
mvn clean package
java -jar target/led-scheme.jar
```

Тесты (доменная логика, контроллер цепочек, расчёт нагрузки, экспорт схем/
масок, механизм обновления, дымовой тест UI):

```
mvn test
```

## Сборка нативного дистрибутива

`jpackage` (входит в JDK) собирает нативный лаунчер со встроенной средой
выполнения — Java на машине пользователя не требуется.

**Windows** (локально, `mvn package` сначала):

```
jpackage --type app-image --name "LED Scheme" ^
  --input target/app-input --main-jar led-scheme.jar ^
  --main-class com.vjstb.ledscheme.App --dest target/dist
```

(`target/app-input` — папка, куда положен только `led-scheme.jar`.) Результат:
`target/dist/LED Scheme/LED Scheme.exe` + папки `app` и `runtime`. Для
установщика (`--type exe`/`msi`) дополнительно нужен WiX Toolset.

**macOS** — собирается в CI (`.github/workflows/release-macos.yml`, GitHub
Actions, `macos-latest`), т.к. `jpackage` умеет собирать `.dmg` только на той
ОС, под которую собирает; запускается автоматически по пушу тега `v*` или
вручную (`workflow_dispatch`) с указанием тега существующего релиза.

## Дальнейшее направление

- Экспорт пресета After Effects — формат уточняется, кнопка заготовлена
  (неактивна) в «Генерация масок».

  оборудования между рабочими местами, раздача обновлений, облачный архив
  проектов.
